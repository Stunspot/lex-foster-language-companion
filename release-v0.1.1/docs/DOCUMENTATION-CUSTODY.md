## Source authority

Product behavior comes from the canonical source skill and exact emitted distributions. Host behavior comes from observed host evidence. Documentation readiness comes from Hesperos authorship, structural lint, manual journey review, independent accessibility review, and any separately retained browser or user tests.

When sources conflict, current executed behavior and versioned package bytes govern technical fact; explicit owner decisions govern product identity and authority; unverified host or model behavior remains `not tested`.

## Ownership and change triggers

Collaborative Dynamics owns product and documentation custody. Reopen affected pages when:

- package paths, names, versions, or host contracts change;
- a workflow, boundary, template, or evidence state changes;
- a recurring support problem reveals missing recovery;
- a language, cultural, privacy, or accessibility defect changes safe use;
- verification upgrades or invalidates a claim;
- a document link, command, or example fails.

## Evidence limits

Markdown lint can detect selected structural defects. Manual inspection can challenge information scent, task flow, examples, and claim language. Neither proves screen-reader usability, representative-user success, formal conformance, host activation, language correctness, or professional approval.

The documentation manifest, Hesperos evidence packet, authoring response, task receipt, authorship receipt, and independent review receipt bind the exact current bytes. If a customer document changes, regenerate those receipts before claiming current documentation custody.
