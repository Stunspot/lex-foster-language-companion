# Accessibility statement

Version 0.1.0 uses text-only repository, documentation, and GitHub Pages surfaces. No information depends on an image, color, sound, position, gesture, or animation.

## Authored accessibility properties

- one descriptive title per page;
- logical heading order;
- real Markdown lists and simple tables with header rows;
- meaningful link text that predicts the destination;
- literal control and artifact names;
- no color- or position-only instructions;
- examples that state purpose and expected result;
- procedures with prerequisites, observable success, and recovery;
- text that can be selected, copied, translated, enlarged, and read by assistive technology;
- no timed interaction in the package;
- no required mouse, touch, microphone, or audio path.

## Cognitive accessibility

Customer pages lead with the task, reveal depth progressively, keep important warnings near the affected action, and distinguish product truth from evidence limits. Users may begin from a short natural-language request instead of a configuration form.

## Language accessibility

Documentation is currently authored in English. The product can help translate the documentation, but a model-generated translation is not an accessibility-reviewed localized edition. Technical names, commands, placeholders, and paths must remain exact.

## Evidence boundary

Hesperos authored the documentation with accessibility in the structure. Automated Markdown lint and manual semantic review are bounded checks. Browser rendering, keyboard navigation, screen-reader behavior, zoom and reflow, cognitive usability, representative-user testing, and formal WCAG conformance were not yet established unless the retained verification record says otherwise.

Report an accessibility barrier through [Support](../../SUPPORT.md) with the page, task, access method, observed barrier, and preferred outcome. Do not include private learner or translation data.
